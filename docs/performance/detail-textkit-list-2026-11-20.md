# UIKit / TextKit 详情列表首轮对比

正式详情入口通过设置开关选择 UICollectionView 或 Texture。两个列表都接收同一组离线页面，保留分页、热评、楼层跳转及媒体加载流程。默认入口使用 Texture。

## 测量方法

旧版数据取自[阶段 1 基线](detail-texture-baseline-2026-11-20.md)。新版从相同的页面入口、相同的样本楼层计时，每个场景各 20 次。表中时间为毫秒。第 2 页落点为 13 楼。回滚由 24 个刷新周期驱动，包含滚动动作本身，两端都等待第 3 页末行具备布局后开始。Texture 能在屏外创建节点，UIKit 对屏外行先提供估算位置。回滚数值反映各列表实际预热策略下的表现。

“目标行就绪”记录查询到已安装内容的行，“正文可见”要求正文连续两帧与视口相交。UIKit 会在异步安装内容后刷新整行高度，因此两个引擎最可比的终点是正文可见和 ANSI 图片可见。测评初次打开时隔离本引擎首个 ANSI 块的磁盘缓存，同一轮随后重开。页内首段与首个报告图分别计时。内存取显示刷新时采样的最高进程占用。

## UI 对照

47 组楼层加投票主楼，浅色与深色、默认与 +8 pt 字号，分别采集适用的媒体占位态和加载态。楼层截图全高、1 像素/pt。以前后高度差不超过 1 pt 做筛选，并记录任一 RGB 通道差值超过 16 的像素占比用于人工排序。

| 设备 | 截图对数 | 高度差 ≤ 1 pt | 超出容差 | 最大高度差 |
|---|---:|---:|---:|---:|
| iPhone Air | 256 | 0 | 256 | 613.0 pt |
| iOS 26.5 模拟器 | 256 | 10 | 246 | 339.0 pt |

真机差异最大的是 832584 主楼的 +8 pt 占位态。旧版 2545 pt，新版 3158 pt。截图中段落之间有整行空白，代码会在相邻段落间插入两个换行。893437 主楼还可见列表编号和缩进变化，1067722 的 6 楼则有引用框内边距及作者栏差异。楼层高度与操作区、正文都有关系。逐项验收仍在进行。

首轮真机长楼截图时，UIKit 的整行截图调用返回失败，独立测试宿主的断言触发 SIGTRAP。符号化栈指向测试宿主的截图闭包。当前驱动对这类楼层使用已安装视图的图层重新取图，逐项记录捕获方式。
真机涉及 4 张。示例为 post-832584-1-0-light-8-placeholder。
模拟器同样涉及 4 张，均为 832584 主楼的 +8 pt 样本。

## 楼层长按与排版调整后的复测

使用同一套页面驱动与 Texture 基线对照。调整涵盖段距、列表缩进、引用内边距、作者栏和底部操作排列。每台设备各有 256 对截图，表中高度差取绝对值。

|---|---:|---:|---:|
| iPhone Air | 12.33 → 3.67 pt | 0 → 38 | 613 → 111.67 pt |
| iOS 26.5 模拟器 | 12.33 → 5.00 pt | 10 → 38 | 339 → 371 pt |

iPhone Air 的 160 对高度更接近 Texture，74 对持平，22 对变远。1067722 帖 6 楼在大字号下的引用缩进和作者栏对齐已经接近，正文仍有换行差异。893437 主楼是两台设备当前的最大偏差；模拟器的大字号样本比 Texture 矮 371 pt。[引用楼层三版对照](../../.build/detail-gesture/quote-comparison.jpg) · [真机逐楼对照与速度数据](../../.build/detail-gesture/phone-comparison/index.html) · [模拟器逐楼对照与速度数据](../../.build/detail-gesture/sim-comparison/index.html)

iOS 17.5 模拟器用实际触摸验证了三个入口。长按末字右侧 2 pt 出现系统选区和拷贝菜单，长按明显的行尾留白或楼层号打开楼层菜单。从该菜单进入复制面板，可读取完整原文 `短**回复** ！`。iOS 17.5 和 26.5 的模拟器分别点按系统拷贝，并从剪贴板读回选中的 `回复 ！`。iPhone Air 验证了相同位置的触摸分派和楼层辅助功能操作；真机 XCTest 手势驱动在连接 IDE 时退出，未取得真机长按弹层的自动化结果。

## 测评报告图的耗时分解

在同一台 iPhone Air 上用 Release 独立测试宿主回放当前 TextKit 列表。第 2 页跳楼、第 3 页回滚、测评首次出图和缓存命中各运行 20 次。在正式渲染入口、主楼 Markdown 解析与排版、视图安装、行高测量、终端快照及缩略图生成前后记录单调时钟，与同轮显示回调对齐。以下时间含异步等待，各阶段分位数分别计算。测评样本为 1067722 主楼，首个标签的报告图为 1750 × 3704 像素，生成时分三块截取。这里的首次出图指该报告的磁盘缓存缺失，WebKit 与 App 进程可能已经预热。

| 首次生成报告图 | P50 ms | P95 ms |
|---|---:|---:|
| 主楼 Markdown 解析 | 0.44 | 0.47 |
| 主楼 TextKit 排版与分块绘制 | 0.34 | 0.67 |
| 主楼安装内容视图 | 2.26 | 2.79 |
| 创建 WebView | 4.14 | 4.89 |
| 加载本地页面至检测到脚本就绪 | 87.67 | 90.26 |
| xterm 处理 ANSI、绘制与等待刷新 | 56.39 | 73.93 |
| 调整 WebView 尺寸后等待两帧 | 32.86 | 33.03 |
| 三次 WebKit 截图合计 | 79.53 | 90.00 |
| 三块 PNG 编码与落盘合计 | 89.09 | 94.28 |
| 从分块文件合成并编码完整 PNG | 114.55 | 118.39 |
| 主线程从完整 PNG 生成展示缩略图 | 52.87 | 53.44 |
| 从页面开始渲染到报告图可见 | 558.94 | 582.96 |

**磁盘缓存命中。** 读取清单并核验文件的 P50 为 0.29 ms，主线程生成缩略图为 52.73 ms。20 次中，每次的最长帧间隔与缩略图生成至少重叠 40 ms，重叠占比中位数为 98.6%。每轮包含约 9 次行高更新，合计 P50 为 9.53 ms。该测评主楼的 Markdown 解析和排版各不到 1 ms。第 3 页回滚时最长帧间隔 P95 为 17.70 ms，当前回放首先应关注报告图出现的时刻。[逐轮阶段与帧时间戳](../../.build/detail-profile/profile038.json)

**首次生成。** 先将三块截图分别编码、写入磁盘，再读回、合成并编码完整 PNG。这两段在同一轮的耗时相加后，P50 为 204.1 ms。可以试验逐块画入有像素上限的目标位图，最后编码一次，同时验证超长图的峰值内存、切栏取消和放大后的图片一致性。204.1 ms 包含最终合成与编码，实际可省的时间须用原图尺寸和相同画质重新测量。

**同尺寸缩略图复用实验。** 另一次真机运行中，每轮先生成一次新报告，再打开同一帖子两次。一组照常从完整 PNG 生成缩略图，另一组复用该轮相同文件、相同目标像素尺寸的 UIImage。两组都读取磁盘清单，也都保留一份实验缩略图。20 轮中，两种先后顺序各占 10 轮，复用组全部命中。表中单位为 ms。[配对实验原始记录](../../.build/detail-profile/profile038ab.json)

| 同一轮中再次打开测评帖 | 磁盘命中后重新生成 P50 / P95 | 复用已生成缩略图 P50 / P95 |
|---|---:|---:|
| 准备缩略图 | 53.04 / 53.78 | 0.01 / 0.01 |
| 首张报告图可见 | 90.49 / 95.33 | 49.10 / 63.93 |
| 本轮最长帧间隔 | 65.69 / 97.13 | 30.15 / 43.47 |
| 出现超过 50 ms 帧间隔的轮数 | 20 / 20 | 0 / 20 |

20 对里报告图均提前显示，逐对计算的节省时间中位数为 41.65 ms；逐对计算的最长帧间隔缩短量中位数为 34.11 ms。首次打开或内存缓存被回收时仍需生成缩略图。可优先试验按报告内容标识和目标像素尺寸缓存预览，并将未命中时的 ImageIO 读取与解码移出主线程。生产缓存需要按解码后的字节数设上限，在离屏、复用和切标签时校验任务身份。本次实验的两组都保留同一张图，不能用这组内存数字估算正式缓存的额外开销。后台解码和首次生成流水线的收益均待独立验证。计时与复用探针仅用于独立测试宿主。
