# 首页加载性能验证（2026-11-04）

> 本文记录当时的性能测量。后续已移除 App 启动动画和设置开关，当前只保留系统静态启动屏；以下数据不代表最新版本的重新测量。

## 范围与方法

iPhone Air 真机 Release，通过局域网安装和读取日志。使用 URLSessionTaskMetrics；相同进程首次首页 GET 完成后，间隔 3 秒追加两次相同 GET。重启进程重复一轮，共六个请求。保留既有共享 URLSession、请求头和缓存策略；重复请求只下载，不更新界面。所有样本均包含 HTTP/2 网络事务，返回 200；本地缓存事务没有正文，不作为网络样本。没有展示上次首页。

临时探针已移除。原始测量数据位于 `.build/startup-profile/release/warm-connection-validation.json`（本地构建目录，不纳入版本控制）。

单位：毫秒。总计为 URLSession 任务耗时，其余列为网络事务阶段。TLS 包含于建连及发出前阶段，不能重复相加。破折号表示无该阶段时间戳。

连接池已正常复用。首次请求发出前 373–490ms，TLS 360–468ms；后续发出前约 2–3ms，但首字节仍需 985–1118ms。两轮后续请求均比各自首次快，不能将全部差值归因于 TLS，因为远端响应时间同时波动。样本不足以推导长期分位数或保证收益。

首字节等待包含网络往返、CDN 和服务端处理，当前客户端日志无法进一步区分。不能直接称为“后端执行耗时”。在进程首次启动时，没有现成连接可保证复用；额外预热请求也需建连，是否有效取决于能否与必要的启动工作重叠。

## 前序验证与保留改动

- 测量时关闭启动动画。曾验证在动画期间提前请求可提前约 750ms；当前启动动画已移除，该对比仅作历史记录。
- 从 AppDelegate 回调起算，创建根界面约 29–35ms，调用骨架加载约 77–80ms，viewDidAppear 约 115–118ms；这些不是物理首帧测量。
- 前序两次分阶段请求总耗时约 1.82–1.86s，HTTP 占约 93%。Cookie 同步约 39–41ms，解析含重复校验约 56ms。
- 保留同一不可变 HTMLResponse 的验证结果复用，避免请求层与业务层重复扫描 HTML。探针测得首次检测约 10–25ms，复用近零；不复用不同请求的内容或检测结果。
- 通知和签到延后 5 秒的四轮交叉试验未发现稳定提速，因此未保留延后改动。
- 检测结果复用通过 180 项 SwiftPM 测试，以及 28 项相关 runtime 测试；设置相关测试 36 项通过。正式 Release 构建验证。

## 结论和后续边界

本轮不调整连接池：现有共享会话已经完成连接复用。当时关闭动画的测量中，客户端初始化只占较小部分，进一步削减几十毫秒无法解决约一秒的首字节等待。

下一步有价值的实验是相同设备跨网络对照，或者结合服务端/CDN时序定位远端等待；需要对应网络条件或服务端观测能力。流式解析可能提前于完整正文展示，但本轮正文仅约 21–108ms，收益有限且会增加解析复杂度，不应作为当前首选。
