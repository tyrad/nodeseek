# 详情页分页与回弹 E2E 用例

从仓库根目录运行。前三条用 WebDriverAgent 在完整 App 中通过「设置 → 调试 → 详情测试」打开站点帖子；请求、解析、渲染和手指操作均走正式路径。模式由启动参数指定，仅影响本次进程。第四条用独立测试窗口装配正式 Interactor、Presenter 和 TextKit 控制器，用本地 HTML 响应控制到达时间，由 AXe 在模拟器屏幕上拖动。

| 编号 | 命令 | 数据与环境 |
|---|---|---|
| 旧版短末页对照 | `make e2e-case CASE=thread-pagination` | 公开帖 1069173，Texture |
| 新版短末页与回弹 | `make e2e-case CASE=textkit-pagination` | 同一帖子，TextKit |
| 跨页回读 | `make e2e-case CASE=textkit-backscroll` | 公开帖 1067259，TextKit |
| 慢响应、错误重试与回弹 | `make e2e-case CASE=textkit-paging-timing` | 合成两页 HTML，本机 AXe 和已安装的 iOS 模拟器 |

真实站点用例沿用项目 daily 测试设备，要求阅读布局和网络可用。只读取公开帖子并更新本机浏览历史。可显式传入 `SIMULATOR_ID`；查看所有编号用 `make e2e-list`。时序用例无需登录和模型密钥。对同一测试设备顺序运行。

## 1、2 · 连续阅读、短末页、跳页往返

1. 冷启动并打开 1069173 的第一页。按用例核对实际渲染器。滑动调出页码面板，从末页按钮读取总页数，再点第一页返回。
2. 向后读，直到真实视口内出现第 11 至 20 楼之一。验收同时要求当前进程日志出现第二页成功追加且追加数量大于零。单有页码变化不足以通过。
3. 当前样本末页为第 2 页。连续滑到底，以「加载新评论」按钮和属于末页的可见回复确认已到底。即使第 9、10 楼也在屏内，页码仍应为「第 2 页，共 2 页」。
4. 新版记录末楼在屏幕上的纵坐标，再向上拉过底部并松手。回弹后连续两次读取同一楼的坐标，偏差均须在 1 pt 内，期间没有新的自动分页请求。
5. 从面板直接跳末页，核对显示楼层属于末页、页码正确，再通过面板回第一页。以首批楼层和可读正文验收。保留面板、连续续页、两种末页入口和回到第一页的截图。

若线上回复增长到第三页或更多，脚本仍验收连续续页和直接跳末页；原样本的「第二页不足一屏」应单独记为数据变化，需另选短末页帖子或使用下方固定样本验证。

## 3 · 第三页 21 楼回滑至第二页

1. 从 1067259 第一页进入新版详情，连续向后读。该帖首页热评也有 #21。以第三页普通回复的评论 ID `14280453` 和页码共同确认到达目标。
2. 反向拖动，要求屏内出现第二页 #13～#16 中至少一个原楼层。记录其实际 ID 和截图。
3. 再次向后读，回到同一个第三页原楼。第一、二、三页各应只请求一次。预取可以更早开始，读取下一页本身不会让此检查误判。
4. 每段操作最多使用 45 次拖动；用完仍未到目标即失败，报告最后可见的楼层标识。样本被删除、详情加载失败和成功加载后无法回滑要分别记录。

## 4 · 可控时序

固定数据为第一页 25 条回复、第二页 3 条。偶数楼提供可见 Markdown，奇数楼走网页富文本回退。每一步等待实际请求、列表行数或系统手势状态；12 秒为单步失败超时。驱动的三次拖动时长均为 1 秒。

| 时点 | 操作与触发条件 | 通过条件 |
|---|---|---|
| T0 | 将已排版的第一页定位至页底，接住第一次第二页请求 | 请求顺序为 1、2；回复仍为 25 条 |
| T1 | 手指拉过旧页底 20 pt 后，第一次请求返回超时 | 加载指示结束，回弹停稳；行数不变，同次手势未再次请求 |
| T2 | 再次拖动，确认第二页重试且越界超过 20 pt，交付成功响应 | 控制器已收到 28 条回复，列表仍保持旧行数；在响应前后的同一次手势中，旧页底移动不超过 1 pt；另以原页末楼的屏幕坐标核对重试前后的阅读位置 |
| T3 | 松手并等系统结束回弹 | 列表增加恰好 3 行，原阅读位置偏移不超过 1 pt |
| T4 | 在第二页末尾拉过底部 20 pt 以上再松手 | 停稳后偏移不超过 1 pt，行数不变，总请求顺序为 1、2、2 |
| T5 | 手指点击末尾的「加载新评论」，服务端返回原第二页三条回复 | 出现「暂无新评论」，只重新请求第二页一次；行数不变，位置偏移不超过 1 pt |

时序回放把请求页序列、响应时越界距离、追加位置差和最终位置差写入本次目录的 `measurements.json`，逐次采样在 `scroll.csv`；命令同时验证 XCTest 成功和外部手势确实执行。实站报告包含 `junit.xml` 和分步截图，失败时先看对应运行目录的失败截图和第一个未满足的断言。

## 相邻回归

`make xcode-test-class TEST="DetailCollectionTests DetailFloorAnchorTests DetailEntryHintTests"` 检查快速甩动落点预取、跳页期间旧请求隔离、筛选续页、重复页交付、签名延迟时楼层高度、楼层跳转与分页提示卡片。这里的断言补充实站手势覆盖。模拟器测量的是屏幕位置；真机触觉和用户当时的网络延迟需独立验证。

## 2026-11-22 合并后实测

- iOS 26.5 的三条实站用例最终均通过，各自的 JUnit 均有一条实际执行记录。帖子 1069173 在连续阅读到末尾时同时显示 #9～#12，Texture 与 TextKit 均显示第 2 页。直接跳末页时两版都显示 #11、#12。帖子 1067259 的新版回滑实际经过第 2 页 #16，回到原 #21；前三页的请求顺序为 1、2、3。
- 时序测试分别核对两种位置：列表的可滚动底部会随旧楼层重新测量而移动；阅读位置取同一个末楼在屏幕上的位置，并扣除手势越界距离。以第二页响应交付前一刻的页底作为追加基准。两次独立手势开始时的绝对滚动位置不适合直接相减。
- iPhone 15 Pro / iOS 17.5 与 iPhone Air / iOS 27.2 的时序回放均通过。第二页成功响应到达时，手势分别越界 30 pt 和约 27.7 pt。两台模拟器测得重试时原末楼位置变化、追加后位置偏移、第三次拖动停稳后的偏移和手动刷新后偏移均为 0 pt。请求顺序均为 1、2（超时）、2（重试成功）、2（手动刷新）。
- 合并后的 SwiftPM 全量 213 项及 iOS 17.5 详情页、楼层定位、页码提示、请求隔离等 208 项回归均通过。
