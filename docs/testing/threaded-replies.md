# 楼层「查看相关对话」测试计划

以下是功能实现后的验收用例。以可控页面响应断言回复关系、裁剪结果与实际请求次数，再在 Xcode 单测与模拟器中验证菜单、面板交互与阅读位置。[开发方案](../plans/2026-11-25-threaded-replies.md) · [效果图](https://github.com/tyrad/nodeseek/issues/12)

## 三页固定样本

使用合成帖 `12000`，评论 ID 取 `90000 + 楼号`，刻意与楼号不同。第 1、2 页各十楼，第 3 页到 27 楼，其余未列出的楼用普通正文填充。第 1 页另放一条第 23 楼的置顶热评副本，沿用相同评论 ID，副本无 Markdown。优先复用 [CommentQuoteSourceTests](../../nodeseekTests/SharedCore/CommentQuoteSourceTests.swift) 的页面配置结构与原文样例。

| 页 | 楼层与内容 | 应登记的直接关系 |
| --- | --- | --- |
| 1 | `#3` Mori 发问；`#8` Alice 用标准回复前缀回应 Mori；`#9` 是另一段对话的起点 | `3 → 8` |
| 2 | `#15` 追问 8；`#18` 引用 15，引用正文又嵌套了 8 的旧话；`#19` 回复 9 | `8 → 15`，`15 → 18`，`9 → 19` |
| 3 | `#23` 回应 3；`#27` 回应 23 | `3 → 23`，`23 → 27` |

选中 `#3`，第 1 页已就绪时显示 `[8]`，第 2 页到达后显示 `[8, 15, 18]`，第 3 页到达后显示 `[8, 15, 18, 23, 27]`。相对根的深度是 `[1, 2, 3, 1, 2]`，最终计数为 `5`。选中 `#8` 时上方祖先为 `[3]`、下游为 `[15, 18]`；选中 `#15` 时上方祖先为 `[3, 8]`、下游为 `[18]`；选中 `#9` 上方无祖先、下游为 `[19]`；选中 `#27` 上方祖先为 `[3, 23]`、下游为完成空态。

## Markdown 与索引单测（`SharedCore`）

| 输入或改动 | 断言 |
| --- | --- |
| 生成器产出的单回复、同行多前缀、换行分隔前缀、多块引用、引用与回复混合；同一楼既回复又引用 | 全部不同直接目标均入索引，同一条边只有一次；不强校验链接内页码 |
| `#18` 的外层引用头指向 15，嵌套引用指向 8；正文、围栏代码块、行内代码中另放相同链接 | 唯一直接父楼是 15；单独只有普通正文链接、代码或 `@用户名` 时，集合为空 |
| 其他帖子、外域、非数字锚点、文字与目标不一致、自引用或未来楼号 | 忽略无效目标，仍保留同一评论里的合法标准前缀 |
| 纯 Markdown 规则（不做 HTML 兜底）：正常评论 `hasVisibleMarkdown == false` 但 `markdown` 有效；HTML 含楼层链接但 `markdown == nil`；受限页或屏蔽/删除评论 | 正常评论可建边与展示；`markdown == nil` 不从 HTML 建边或反推正文；受限页内容不入索引 |
| 重复父引用裁剪：`#18` 挂在 `#15` 下展示；纯引用无正文回复 | `#18` 展示文案剥离指向 15 的前导引用块与回复前缀，只留实际正文；剥离后为空时回退原 Markdown |
| 先交付第 3 页再交付第 1 页；首页热评掉榜刷新第 1 页 | 23 的正式内容与 `3 → 23` 关系保留，首页热评掉榜不误删第 3 页正式楼层 |
| 将 18 的直接目标从 15 改成 9 再刷新第 2 页；删除正式评论并刷新该页 | 15 的旧边消失，9 可找到 18；删除后不留孤立显示行 |
| 一楼同时回复 8 和 23；跨四级以上连续对话 | 两个父楼分别作为根都能找到该楼；从 3 展开时只计一次；深度保留真实值，视觉缩进上限为 3 |
| `temp-script` 含 `postData.postPageCount` | `PostDetail.totalPages` 正确解析页数 |

## 分页调度与会话集成测试

使用可暂停、失败、支持可控时钟的假分页服务。按「帖子、请求页」记录实际底层调用，正常翻页也计入；每个场景重置服务和索引。

| 操作 | 应观察到的结果 |
| --- | --- |
| 正常阅读第 1 页，打开 `#3`；第 2 页完成后、第 3 页挂起时关闭；重新打开 `#9` | 立即看到 `[19]`。前两页各请求一次；第 3 页若取消则仅重拉第 3 页。关闭期间不发起后续页 |
| 正常阅读与扫描同时请求第 2 页，关闭面板，交付第 2 页 | 底层只有一个第 2 页请求，正常阅读仍收到结果；独立扫描不会驱动主详情跳页或触发动作页预热 |
| 三页全部查完，在 `#3`、`#8`、`#9`、`#27` 之间切换 | 请求记录仍为 `[1, 2, 3]`，零新增请求；各根结果与固定样本一致，计数不含根 |
| 从第 2 页进入，先扫描 `#15`（回复第 1 页的 `#8`）再查看 `#3`；另测从第 2 页扫描无上游父楼的 `#12` | 扫描 `#15` 时先补查第 1 页补齐祖先 `[3, 8]`，再扫第 3 页（请求 `[2, 1, 3]`），换看 `#3` 零新增请求；扫描无父楼的 `#12` 仍仅查 `[2, 3]`，不误查第 1 页 |
| 第 2 页首次失败或命中 Cloudflare 挑战后重试 | 暂停自动扫描，仍可读 `#8`，提示重试；重试后成功继续第 3 页，成功前不报完成或空态 |
| 长帖节流与单轮上限：模拟 25 页帖（单轮上限 20 页，每 3 页停顿）；停顿期间关闭面板 | 每满 3 页触发停顿，满 20 页暂停并提示「继续查找」；停顿期间关闭面板立即取消等待，不再偷发下一页 |
| 三页扫完后本地回帖成功或末页增长；另测增长到第 4 页 | 前两页不重取；复查第 3 页，必要时请求第 4 页，新回复只出现一次 |
| 游客态扫过帖子 → 登录成功 / 退出登录 / 受限态变化 → 再次打开同帖；切换根时旧订阅回调晚到 | 旧会话索引立即清空，迟到回调被丢弃；屏幕只显示当前会话、当前帖、当前根的数据 |

## 菜单、面板与模拟器交互验收

1. **入口边界**：在评论楼层（正整数楼层号）右侧楼号左侧展示单色细线转折按钮（`arrow.turn.down.right`，跟随楼号字体 `.small` + light），点击图标或楼号热区均可直接打开「查看相关对话」面板，且长按菜单与 VoiceOver 自定义操作保留该项；主楼（`#0`）既不显示分支按钮也不出现长按项；头像长按预览、复制、只看 TA、链接和底栏引用保持正常。
2. **层叠与排版**：对照效果图检查两个分支缩进、左侧分支连接线、最大三级缩进及四级以上「回复 `#上级楼层`」提示；确认重复父引用已被裁剪，无原文楼层显示占位文案。
3. **阅读位置保持**：在面板滚动到后方分支（如 `#23`）时插入前方新回复（如 `#15`、`#18`），当前可见楼层在视口内的位置保持稳定；关闭面板后主详情列表仍在打开前的滚动位置。
4. **状态、主题、字号与多语言**：检查查找中、达到单轮上限可继续查找、失败可重试、已完成总数、完成空态；检查浅/深色模式、大字号与辅助字号，以及 `zh-Hans` / `zh-Hant` / `en` 三语文案。
