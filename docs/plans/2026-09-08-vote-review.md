# 原生投票改动复查与重构

范围：复查本次对话形成的投票功能及 8a2209d，不混入其他尚未提交的分栏、终端和图片功能。

## 发现与方案

1. 提交路径由 ViewModel 主动读取结果，View 又在收到服务通知后排队刷新，造成重复读取。将可见性、会话变化和投票通知统一交给 ViewModel；忙碌操作已有结果回读，避免重复排队。
2. NodeSeekVoteService 同时承担 Cookie 同步、HTTP 签名、WebView 回退、JSON 验证和请求合并。拆出类型化投票客户端；服务只管理共享请求、提交互斥和会话生命周期，依赖客户端协议。
3. 网页按钮删除后仍保留 open=web 分支和楼层预览的专用转发回调。移除无来源的路由与回调。
4. 保留有证据支持的防护：站点验证回退、提交前服务端校验、写入不重试、账号切换丢弃旧结果、Texture 祖先缓存失效。它们分别解决网络/业务/布局的真实边界，并非无条件兜底。

## 验证与约束

先证明提交产生重复读取，再验证修正后的请求次数。补充账号切换、提交与读取交错、服务端失败文案等测试；复用已有签名、投票交互和图文混排回归。保持当前 UI 和投票语义，不新增刷新/网页按钮，不向真实投票写入。

## 落地与取舍

- `NodeSeekVoteAPIClient` 处理传输和响应，`NodeSeekVoteService` 作为同一投票接口的包装层处理共享任务；用现有 `NodeSeekVoteServing` 注入客户端，未再引入一组同形协议。
- WebView 请求用 `WebRequest.load/submit` 表达，不再用可空 ids 切换整个请求路径，也删除测试专用的运行时 override 分支。
- ViewModel 统一管理可见性及通知。投票通知带服务实例和投票编号，避免不同实例互相刷新；忙碌操作已有读取或结果确认，不再额外排队。View 只负责展示、测量和提交确认。
- 合并读取用同一条循环处理成功与失败：提交使旧读取失效并取消它，等待者读取新状态。原实现只有成功返回才检查版本，旧读取失败可能直接覆盖新状态。
- 会话切换取消读取和排队中的提交，清理互斥状态。旧提交完成时不能清理新会话任务或发布通知；进入 WebView 脚本前再次检查取消。已经发送到服务器的写入无法撤回，继续保留结果回读及禁止自动重试。
- 保留两个 generation：服务隔离账户请求，ViewModel 防止异步返回覆盖已重置的界面状态；保留读取 token，避免旧等待者清掉较新的共享任务。它们分别保护不同的状态边界。
- HTTP 200 中的 `success:false` 保留服务端错误文案，不再统一误报“数据不完整”。
- 移除 `open=web` 专用分支和仅服务于旧按钮的楼层预览回调。原生投票路由、真实站点验证回退、混排布局修正继续保留。

## 证据

新增真实卡片回归在重构前失败：进入页面并提交后读取次数为 3，预期为 2。结果包为 `.build/vote-review-before.xcresult`。所有投票写入测试使用模拟响应。

重构后 `make xcode-build-tests` 通过，145 项投票及详情回归全部通过（`.build/vote-review-after.xcresult`）。重复读取用例从 3 次恢复为 2 次；新增测试覆盖旧读取成功/失败的失效处理、账号切换取消提交、同投票写入互斥、可见性及通知来源隔离、业务失败文案。浅色混排截图及既有暗色/动态字体布局测试通过；`git diff --check` 通过。本轮未安装真机、未创建新提交。
