# 原生关注与被关注

## 范围

自己的个人页「关注」「粉丝」共用一个原生 UIKit 页面，不使用 Texture。顶部固定原生 UISegmentedControl，左为「关注」、右为「被关注」；从对应统计入口进入时默认选中对应 Tab。列表正文支持左滑到「被关注」、右滑回「关注」，到边界不循环；屏幕左边缘保留系统返回手势。点击分段和滑动使用同一套切换逻辑，保留数据及位置。他人的粉丝统计保持只展示数量。

列表保留头像、昵称、简介与等级、鸡腿、星辰、帖子、评论、被关注数。缺少简介时展示 UID，点整行进入现有原生个人页。只读展示，不加入关注、取消关注、转账或私信写操作。

## 数据证据

已在浏览器核对网页 `/fans?type=fans`、公开 fans 脚本和两个接口的实际响应：

- GET `/api/fans/follow` 返回当前账号关注的人。
- GET `/api/fans/fans` 返回关注当前账号的人。
- `success` 与 `memberList`，每位用户字段有 `member_id`、`member_name`、`rank`、`coin`、`stardust`、`bio`（可 null）、`nPost`、`nComment`、`fans` 等。
- 两接口一次返回完整名单，无分页参数，不支持指定其他账号。
- 复用现有 URLSession、请求指纹和 AvatarImageLoader。未登录、网络与解析错误不能当成空名单。

## 状态

两个 Tab 独立保存数据、错误、加载状态和滚动位置。首次加载每人一个整块骨架，加载成功后切回不重复请求，支持下拉刷新和失败重试。后台返回的另一 Tab 数据不能改变当前可见列表。刷新失败保留原名单，过时请求不能覆盖新结果。

浅深色采用系统动态色，系统字体支持大字。导航为原生 push/pop，用户主页返回后仍在原 Tab 和位置。

## 验证

接口路径、空数据与失败、可空简介、独立缓存、并发切换、刷新失败保留与旧请求保护；页面测试覆盖初始 Tab、骨架、浅深色、大字、切换缓存与滚动位置、空态和原生用户主页往返。页面验证使用模拟数据，真实接口在浏览器核实，不能代替真机登录态全流程检查。
