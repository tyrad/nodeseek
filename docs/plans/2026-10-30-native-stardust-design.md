# 星辰账簿原生页 · 第二版方案与实现

按第二版实现。使用 UIKit 的 UITableView 与普通 cell，不使用 Texture。

## 依据与范围

已在浏览器核对 https://www.nodeseek.com/stardust/list?member_id=31037 。网页标题为「星辰账簿」，列表按时间倒序，首屏十条，底部「加载更多」。可见字段包括变动值、变动后余额、来源与接收用户 UID、原因、时间，以及记录 ID、Ref ID、Comment ID。示例用户当时余额为 11，首条为来自 UID 70992 的点赞，+1，变动后余额 11。

示意图使用上述页面的实际可见内容，属于布局示意，并非运行截图。已核对网页脚本：类型包括系统、管理、转账、点赞、购买邀请码；转账记录 diff < 0 时反转箭头，peer_id 缺失时仅显示账户本人。未知类型保留原文。本稿以项目已定稿个人页为主要视觉依据。

## 布局

- 个人页的「星辰」入口 push 进入，标准导航栏标题「星辰账簿」，返回保留个人页位置，支持侧滑返回。
- 顶部不另做大卡片：40pt 的 ⭐ emoji（无背景），右侧集中排列 12pt「星辰余额」、28pt 粗数字、12pt 用户名字与 UID。直接使用系统 emoji 绘制星星，适配浅深色；文字间隔 2pt。查看自己时只显示昵称，隐藏 UID；查看他人时保留昵称与 UID。自己的页面与他人的页面共用布局，避免看错账户。
- 下面是「变动记录」和一个完整的分组列表。每行三层：原因与带正负号的变动数；来源头像与 UID → 接收者头像与名字；时间与变动后余额。保留原站双方用户之间的流向，不把它简化成纯文本。头像 28pt，示意行高约 96pt，实际随动态字体增长。
- 原因 16pt semibold，变动数 20pt semibold，来源 13pt，时间与余额 12pt，金额使用等宽数字。列表左右 16pt，内容左右 16pt，圆角 14pt，与个人页一致。
- 黑白灰承载主要内容，顶部星辰图标用暖色点缀。增加、减少均保留明确正负号，不依赖颜色区分。系统动态色映射为 systemGroupedBackground、secondarySystemGroupedBackground、label、secondaryLabel、separator。
- 每条记录均保留双方头像和流向箭头，头像可进入对应用户的原生个人页；箭头不是详情跳转指示。昵称缺失时使用 UID，不为显示昵称额外逐条请求。头像可见尺寸 28pt、点击区域至少 44pt；辅助功能大字模式将双方改为上下排列，流向箭头相应改为上下方向。记录 ID、Ref ID、Comment ID 不在主列表铺开；本期不增加详情页。
- 不加图表、筛选、搜索、逐条浮起的卡片、详情跳转箭头和编辑入口。整行不可点、无滑动操作；用户头像保留查看个人页的导航能力。只读仅限制数据写操作。

## 状态与加载

- 首次进入：余额与约 5 行记录骨架，每条记录只显示一个完整圆角占位块，不拆分头像、文字与箭头，避免全屏转圈。减少动态效果开启时用静态骨架。
- 下拉刷新：保留现有内容，使用原生刷新控件。
- 分页：上拉加载；加载中只在底部显示指示器；失败显示底部「加载失败，点按重试」，保留已有记录；全部加载后显示「没有更多记录」。设计图中的五条为屏幕可见示意，不代表固定分页大小。
- 空列表：显示「暂无星辰记录」，不将余额强制归零。
- 首次失败：显示「星辰记录加载失败」和「重试」。账号资料加载失败时，不从当前分页条数推算余额；余额不可得时显示「—」。
- 顶部余额应来自目标用户的账户数据；每行余额是该笔变动后的余额，两个概念不能混用。

## 实现与验证

- `UserStardustRecord.swift`：记录、分页模型和加载状态。刷新替换记录，分页按 ID 去重，失败保留游标，过时响应不会覆盖刷新结果。
- `NodeSeekUserContentClient.swift`：复用请求指纹与 URLSession。GET `/api/stardust/list?count=10&member_id=<uid>`，下一页追加 `before_id=<cursor>`，使用 `exist_more` 判断结束。已在浏览器核对两页真实响应。
- `UserStardustViewController.swift` / `UserStardustCell.swift`：只读列表、动态颜色、首次静态骨架、刷新、分页及错误重试。双方头像复用现有 AvatarImageLoader，可进入原生个人页。不发起任何写请求。
- `UserProfileViewController.swift`：只将「星辰」入口替换为原生页面。
- 顶部余额使用账户数据，资料请求失败时保留入口传入的账户信息，均不可得时显示「—」。列表和资料独立加载，互不阻塞。
- 验证结果：`make xcode-build-tests` 通过，iPhone 17 Pro / iOS 26.5 模拟器相关测试共 24 个通过、0 失败。
- Xcode `build-for-testing` 与窄范围单测：接口请求与解析、流向、空记录、分页失败与重试、去重、刷新替换、过时响应、刷新失败保留内容。
- App-hosted 页面测试：模拟数据覆盖浅色、深色、骨架、辅助功能最大字体，以及头像进入原生个人页后返回。此测试不能替代真机登录态与真实网络的端到端检查。
