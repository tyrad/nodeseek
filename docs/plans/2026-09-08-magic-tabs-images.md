# 测评帖子分栏与终端图片接入

## 目标

在实际详情页保留 NodeSeek magic tabs，选中栏中的终端原文异步生成彩色图片，图片栏复用既有渲染。原独立验证工具不再作为功能完成的依据。

## 方案与边界

1. 渲染入口先识别 tabs，保留标题与正文块顺序；恢复 `data-ansicode`，不走旧的 ANSI 去色路径。
2. HTTP 正文直接提取原文；隐藏 WebView 在网页替换 pre 前捕获完整原文并存入正文属性。没有完整原文的 xterm 继续提供网页查看提示。
3. 本地打包 xterm 5.5.0，以无持久数据的 WebView 离线渲染；禁止外部请求，正文作为数据传入。
4. 独立串行任务，同内容请求共用工作，所有订阅取消后停止；最多 1000 行、原文 512 KB，每段截图不超过 640 CSS px，操作超时 20 秒。
5. PNG 与清单缓存到 App Caches，内容摘要包含排版、配色、渲染器版本，磁盘上限约 160 MiB。内部仍分段截图，在缓存 actor 上逐段合成一张长图后删除分段文件；常规报告保留原分辨率，极长报告按 1600 万像素和最长边 16384 像素的上限等比例缩小。缓存键更新到合成版，旧分段缓存不复用。
6. 每份报告只生成一张长图，正文按完整长图比例展示，缩略图最长边控制在 2048 像素，图片加载后修正节点高度。打开大图时，按同组分栏顺序汇集报告图与普通图片，补齐未生成报告后交给既有 JXPhotoBrowser；以分栏和点击 URL 定位起始图片，支持跨分栏左右翻页。准备时在图片区域显示系统菊花，不弹提示框、不阻断操作；切换分栏或离开视图时取消，失败支持重试。
7. 原生横向 tab 支持状态恢复；加载、重试和复制正文在详情内容内完成。图片点击复用既有缩放、保存、分享能力，不展示查看提示或内部截图段数，不另建预览控制器。系统界面使用动态颜色，终端图片保留报告配色。
8. TQ 示例帖子 917559 使用同样的 magic tabs，内容为 `tcpquality.ibsgss.uk/r/<id>.png?section=...` 原始报告图片。识别已观察到的五种分栏图片为 report，完整等比展示并保持 section 参数区分；直接复用原图下载、缓存和同组图库，无需重新进行终端截图。

## 风险

- WebView 退化路径的站点脚本可能改变；捕获不到完整原文时应继续降级，不拼接可见终端行。
- 首次 WebKit 启动存在延迟，首屏显示加载状态；离屏取消，回到该栏读取缓存。
- 真机和其他 iOS 版本的 WebKit 截图仍可能存在差异，应将模拟器验证与真机安装状态分开报告。

## 第三栏高度回归

- 实际 NQ 916971 的第三、四栏是外部 WebP（1312×1782、1989×3766），原路径按普通图片限制到半栏宽高度；之前的真实详情测试仅用文字占位第三、四栏，没有覆盖这一情况。
- 分栏内独立图片使用完整报告布局，将上下文传递到图片节点与内部视图，引用内图片沿用同样规则。分栏之外保留普通图片规则。
- 报告显示按栏宽与宽高比计算，不让缩略图像素宽度限制展示宽度，避免缓存缩略图加载后缩小。
- 真实详情进一步复现：子图加载后分栏仍复用 392 点占位高度，实际需要 503 点。子内容回调需先作废当前分栏布局，再通知整行重排；分栏内部缩高也走该路径，避免重建整行。非当前分栏的晚到回调不触发显示布局。
- 验证：实际来源的第三、四栏、切回第三栏、低分辨率缩略图加载前后尺寸，以及普通正文图片的原有高度；随后运行分栏集成测试并重新安装真机。
