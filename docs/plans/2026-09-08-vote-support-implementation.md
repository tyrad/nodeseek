# 帖内投票原生支持

## 目标与范围

基于 [调研记录](2026-09-08-vote-support-research.md)，将 `nsapp://vote?id=3108` 这类投票在帖子正文中呈现为可交互的原生卡片。兼容评论、引用与楼层预览，保留现有图文渲染。

不包含创建、管理投票或公开投票人员分页。未修改其他正在进行的图片、终端和分栏功能。

## 实现

- SharedCore：`NodeSeekVoteParser` 同时识别原始 data-href/href 和已挂载的 vote-panel，保留前后正文与引用层级，排除代码示例和无效编号；`NodeSeekVote` 保留未知票数，不将缺失值显示为零。
- 渲染：新增 `.vote` 内容块，经既有节点工厂创建 `DetailVoteNode`。UIKit 视图按实际内容测量高度，再通知 Texture 更新布局；创建节点时不提前创建 UIKit 视图。
- 请求：`NodeSeekVoteAPIClient` 负责 Cookie、签名、接口响应和 WebView 回退；`NodeSeekVoteService` 依赖投票接口管理共享读取、提交互斥与会话失效。读取优先 URLSession，遇到 Cloudflare/403/503 回退隐藏 WebView；提交仍执行网页预校验和单次写入。
- 交互：支持单选、多选、公开/匿名提示、已锁定与已投票状态。提交前列出所选项并提示不可修改；实际 POST 前重新读取并检查服务端状态。
- 提交结果：不自动重试 POST。无论成功还是超时，都重新读取状态；读取失败时禁用再次提交，直到刷新成功。
- 导航：nsapp 投票链接打开原生投票页，楼层预览也可使用。卡片不展示“打开网页参与投票”和“刷新状态”按钮。重新进入卡片时刷新服务端状态。
- 外观：系统动态颜色、动态字体、无障碍选中/禁用状态；未知票数隐藏，已投票结果使用服务端票数。

## 正文混排重叠修正

用户反馈投票选项覆盖后续正文。使用真实 `PostBodyCellNode` 和 `ASTableNode`、延迟 350 ms 的投票读取复现：内容需要约 493 点高度，但卡片与单元格仍采用初始 160 点高度。此前独立节点测试手动使父节点重排，未覆盖真实单元格的缓存路径。

根因是投票节点使用自定义 UIKit 视图，局部 `setNeedsLayout` 不会自动使 Texture 祖先节点的尺寸缓存失效；现有列表 `relayoutItems` 因而继续复用正文旧高度。

修正仅针对投票节点：高度变化时沿父节点逐层使布局缓存失效，直到所属单元格，再使用既有列表刷新回调。卡片同时裁剪临时越界绘制，避免下一次布局前短暂覆盖正文；不重建投票节点或丢弃用户选项。

新增 `VoteLayoutRegressionTests`，在真实正文单元格中排列投票、两段文字、本地图片和下一条回帖。修正前测试失败，修正后对卡片边界、正文位置、图片位置、下一行起点、结果刷新和无障碍大字体的检查全部通过。

## 投票读取提速与入口精简

移除投票卡片内的“打开网页参与投票”按钮及对应回调，同时更新独立投票页和真实正文的布局测试。

原读取路径需要等待隐藏浏览器动作队列，且页面缓存未命中时先导航首页，之后才请求投票接口。现改为同步既有登录 Cookie、使用相同 User-Agent 和 SHA-1 签名直接 GET `/api/vote/info/{id}`。成功路径不启动隐藏浏览器，不等待页面导航。

仅站点验证或拦截响应回退原 WebView 流程；普通网络错误、登录错误、限流和服务端错误直接反馈，避免再等待一次页面请求。读取超时为 10 秒。保留并发读取合并，不缓存已完成结果；重新进入页面和提交后确认都读取最新状态。提交仍执行原来的网页校验和单次 POST。

加入请求通道及耗时日志（`transport`、`elapsedMs`），用于后续真机观察。当前提速依据是请求链路减少，尚未测量真实网络的端到端耗时差值。

验证：`make xcode-build-tests` 通过；请求服务、投票交互、正文混排和详情页控制器共 132 项测试通过（`.build/vote-fast-read.xcresult`）。新增服务测试覆盖 Cookie 同步、签名、正常读取跳过 WebView、验证回退、并发合并、重新刷新、普通失败不重复请求、登录切换丢弃结果及提交不重试。`git diff --check` 通过；已检查移除按钮后的浅色与暗色混排截图。尚未安装真机。
