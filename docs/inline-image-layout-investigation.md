# 图片遮挡文字调查（2026-11-15）

目标：调查帖子 `1053304` 的 TestFlight 图片错位反馈，复现前不修改业务代码。

当前状态：用户已批准局部修复。已修改 `DetailRichTextView`，让当前视图独立记录排版尺寸，并在共享附件已更新但自身排版仍旧时触发重排和外层高度刷新。原帖反馈是否同源仍未确认。

## 已确认

在 iPhone 14 Pro Max / iOS 17.5 模拟器上，用当前工作区代码复现了共享图片附件导致旧富文本视图不重排的问题。它是内部组件复现，尚不能认定就是原帖反馈的原因。

复现顺序：

1. 渲染含行内图片及前后文字的正文，建立节点 A 并完成视图排版。
2. 用同一份渲染结果建立节点 B，让 B 的图片尺寸提供器返回真实尺寸并执行测量。
3. 向 A 发送同一图片的加载完成回调。
4. 等待重排防抖后，将 A 的布局高度与重新排版的参考视图比较。

两轮独立运行，每轮四种组合各重复五次：

| 顺序 | 图片原始尺寸 | 每轮结果 |
| --- | --- | --- |
| A 正常收到图片回调 | 800 × 240 | 5/5 正常 |
| A 正常收到图片回调 | 800 × 1600 | 5/5 正常 |
| B 先测量，再回调 A | 800 × 240 | 5/5 错误：349 pt 未更新为 170 pt |
| B 先测量，再回调 A | 800 × 1600 | 5/5 错误：349 pt 未更新为 404 pt |

测试关闭真实网络图片视图的创建，手动发送尺寸回调，以隔离网络失败；被测视图挂在父视图中。该测试验证排版不一致，不等价于端到端截图复现。

## 代码路径

- `DetailRichTextNode` 复制 attributed string 时保留同一个可变图片附件对象。
- `calculateSizeThatFits` 中的 `applyCachedAttachmentSizes` 修改附件尺寸，也影响 A 持有的附件。
- A 的 `updateImageAttachments` 看到附件尺寸已相同，跳过重排；其已生成的 CoreText 布局仍是旧尺寸。
- `PostDetailViewController` 存在复用 `headerRenderedContent` 的路径，但原帖现场是否触发上述节点重叠时序，尚未验证。
- 与 `ios/v1.3.1` 比较，`DetailRichTextView.swift`、`PostBodyCellNode.swift` 和 `PostDetailViewController+Table.swift` 没有差异。当前运行的是本地 Debug 构建，不是 TestFlight 原始二进制。

## 连续浏览场景扩展

新增 `FrequentPostBrowsingReproductionTests`，使用真实 `UIWindow`、导航栈、详情控制器、Texture 单元格及图片加载链路。普通组使用实际文件图片加载；延迟组在加载失败后控制成功回调的交付，不直接修改图片附件尺寸。

- 返回列表后重新打开同一帖子，验证缓存命中。
- 原页刷新，复用已渲染正文。
- 向下滚动 700 pt 后返回顶部。
- 详情刚开始渲染时切到下一帖，再返回。
- 图片尚未成功显示时刷新，1 秒后恢复图片文件并向旧、新视图交付成功回调。
- 图片尚未成功显示时切帖再返回，1 秒后恢复图片并交付成功回调。

每种场景重复 10 轮，交替使用 800 × 240 横图与 800 × 1600 长图。最终测试每三轮加入一次三图正文。延迟组先使用空文件触发失败，再于 1 秒后恢复有效文件，并调用实际图片视图的 `applyLoadedImage`；这是失败恢复和晚到回调测试，不是端到端网络限速。

每个检查点验证图片加载成功、现有排版与重新排版的参考高度一致、图片不超出正文高度，并检查图片矩形与文字 glyph run 是否相交。

前两次普通场景运行各完成 40 轮并通过。HTTP 回环慢图方案因应用自动将 HTTP 升级为 HTTPS，未进入目标加载流程，已弃用；全局 URLProtocol 注册也未拦截应用已创建的会话。这些测试环境失败不算应用布局复现，相关尝试代码已移除。

运行命令与前述一致，将 `TEST` 替换为 `FrequentPostBrowsingReproductionTests`。这些是合成帖子数据的页面级测试，不等价于原帖在真实蜂窝网络上的端到端复现。

最终运行：iOS 17.5，6 类场景 × 10 轮，共 60 轮全部通过，无预期失败标记。结果包：`.build/XcodeDerivedData/Logs/Test/Test-nodeseek-2026.11.15_21-20-27-+0800.xcresult`。多图组及文字相交检查均在此轮启用，运行约 67 秒。

结论：在本轮覆盖的连续浏览、返回、刷新、滚动和失败恢复回调顺序中，没有重现图片遮挡文字。前述组件级共享附件问题依然成立，但尚无证据证明这些常见页面操作能触发它。当时未修改业务代码；原帖真实网络环境下的触发条件仍待确认。


## 局部修复

`DetailRichTextView` 为每个附件保存当前视图自己的尺寸快照，重新配置、宽度变化、外观重建及图片重排时更新。图片完成回调先处理附件尺寸，再与该快照比较；即便附件已被其他节点改成最新尺寸，也能识别当前视图仍需重排，并通知外层节点刷新高度。沿用现有 100 ms 防抖，不为相同尺寸重复回调额外重排。
